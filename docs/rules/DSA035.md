# DSA035

Hoist loop-invariant reflection call out of loop.

| Property     | Value                                                                                          |

| Title        | Hoist loop-invariant reflection call out of loop                                              |
| Category     | Performance                                                                                   |

| Refactoring available | ✅                                                                                             |

## 💡 Rationale

This rule fires when a reflection API call (such as `GetType()`, `GetProperty()`, `GetProperties()`, `GetMethod()`, `GetField()`, `GetCustomAttributes()`, or similar) is invoked inside a loop body on a receiver and with arguments that are not modified within the loop, making the result loop-invariant. The reflection call is redundantly executed on every iteration, wasting CPU cycles on identical results.

Reflection operations are inherently expensive compared to direct member access: they involve metadata lookups, security checks, and often heap allocations for the returned `MemberInfo` arrays. In tight loops, these costs compound into significant performance degradation, particularly when the loop operates over large data sets.

Hoisting the reflection call to a variable declared before the loop ensures the operation executes only once, regardless of iteration count.

### ⚡ Performance Impact

Reflection calls such as `Type.GetProperties()` or `Type.GetMethod(string)` perform metadata table scans and allocate arrays on every invocation. Inside a loop iterating N times, the cost is O(N × R) where R is the per-call reflection overhead, compared to O(R) when hoisted. For large N, this difference can be orders of magnitude.

### CWE-405 Mitigation: Asymmetric Resource Consumption

In the context of cybersecurity, this relates to **CWE-405 (Asymmetric Resource Consumption / Amplification)**: an attacker who can influence the iteration count of a loop containing unnecessarily repeated reflection calls can amplify the cost of each request, turning a linear-time operation into a practical denial-of-service vector.

### IEC 62443 Certification: Resource Availability

In the context of **IEC 62443 certification**, computational efficiency in control loops directly supports **FR 7 (Resource Availability)** by ensuring that processing resources are not wasted on redundant reflection operations that could be avoided with straightforward code restructuring.

## 🔦 Code sample

```csharp
public class DataMapper
{
    public void MapProperties_NotOk(object source, Dictionary<string, object> target, string[] propertyNames)
    {
        // DSA035 fires: source.GetType() and .GetProperties() are loop-invariant
        foreach (var name in propertyNames)
        {
            var prop = source.GetType().GetProperty(name);
            if (prop != null)
                target[name] = prop.GetValue(source);
        }
    }

    public void MapProperties_Ok(object source, Dictionary<string, object> target, string[] propertyNames)
    {
        var sourceType = source.GetType();          // hoisted
        foreach (var name in propertyNames)
        {
            var prop = sourceType.GetProperty(name); // GetProperty still uses loop-variant 'name'
            if (prop != null)
                target[name] = prop.GetValue(source);
        }
    }
}
```

## ℹ️ Matched patterns (code is NOT OK)

```cs
// GetType() on a loop-invariant variable:
foreach (var property in knownProperties)
{
    if (record.GetType().GetProperties().Any(p => p.Name == property.Name))
        continue;
}

// GetProperties() on a loop-invariant Type:
foreach (var name in names)
{
    var props = type.GetProperties();  // flagged — type does not change
}

// GetMethod() with constant argument in while loop:
while (i < 100)
{
    var method = type.GetMethod("Execute");  // flagged
    i++;
}

// GetType() on a parameter in for loop:
for (int i = 0; i < arr.Length; i++)
{
    var t = obj.GetType();  // flagged — obj does not change
}
```

## ✅ Not matched patterns (code is OK)

```cs
// GetType() on the loop iteration variable:
foreach (var item in items)
{
    var t = item.GetType();  // NOT flagged — item changes each iteration
}

// GetProperty() with loop-variant argument:
foreach (var name in propNames)
{
    var prop = type.GetProperty(name);  // NOT flagged — name changes each iteration
}

// Variable reassigned inside the loop:
for (int i = 0; i < objects.Length; i++)
{
    current = objects[i];
    var t = current.GetType();  // NOT flagged — current is modified inside the loop
}

// Non-reflection method with same name:
for (int i = 0; i < arr.Length; i++)
{
    var t = svc.GetType("key");  // NOT flagged — not a System.Reflection call
}
```

## 🛠️ Included Code Fixer and Mitigation

The code fix extracts the loop-invariant reflection call into a local variable declared immediately before the loop and replaces all occurrences within the loop body with the new variable.

```cs
// Before:
for (int i = 0; i < arr.Length; i++)
{
    var t = obj.GetType();
}

// After:
var hoisted_obj_GetType = obj.GetType();
for (int i = 0; i < arr.Length; i++)
{
    var t = hoisted_obj_GetType;
}
```
